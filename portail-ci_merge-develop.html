0. Différences avec utilisateurs-ci

  • Pas de Flyway : rien à renuméroter. Les conflits sont du code Angular + package-lock.json.
  • Risque n°1 : la montée Angular 15 → 17 (MR !42, Module Federation host). Si develop est resté en Angular 15, tout fichier develop touché (composants, modules, specs) doit être relu pour la syntaxe/API 17 — le build le dira.
  • Risque n°2 : package-lock.json — ne se résout jamais à la main : on prend le nôtre (Angular 17), on réapplique les dépendances ajoutées par develop dans package.json, puis npm install régénère le lock.
  • Le flux git est identique : branche chore/merge-develop depuis develop-omega → merge develop → MR vers develop-omega → plus tard MR develop-omega → develop.

1. Commandes

FICHIER NOUVEAUGit Bash — état des lieux, merge, build
C:\dev\portail-ci (Git Bash)

La commande comm de l'étape 1 donne la liste des fichiers modifiés des deux côtés : c'est ta liste de conflits avant même de merger.

# Git Bash — portail-ci
cd /c/dev/portail-ci
git fetch origin --prune
git checkout develop-omega && git pull origin develop-omega
git checkout -b chore/merge-develop

# 1) état des lieux AVANT de merger : ce que develop a changé depuis la divergence
git log --oneline --no-merges develop-omega..origin/develop            # commits develop absents chez nous
git diff --stat $(git merge-base develop-omega origin/develop) origin/develop | tail -40
git diff --name-only $(git merge-base develop-omega origin/develop) origin/develop > /tmp/develop-files.txt
git diff --name-only $(git merge-base develop-omega origin/develop) develop-omega  > /tmp/omega-files.txt
comm -12 <(sort /tmp/develop-files.txt) <(sort /tmp/omega-files.txt)   # fichiers touchés des DEUX côtés = conflits probables

# 2) merge
git merge --no-ff origin/develop -m "merge develop into develop-omega (portail-ci)"
git status --short | grep -E '^(UU|AA|DU|UD)'                            # liste des conflits → règles §2

# 3) après résolution
git add -A && git commit --no-edit
rm -rf node_modules && npm ci                                            # package-lock résolu → réinstall propre
npx ng build --configuration development                                 # build shell
npx ng test --watch=false --browsers=ChromeHeadless                      # specs (karma)
git push -u origin chore/merge-develop
# GitLab : MR chore/merge-develop -> develop-omega ; puis develop-omega -> develop quand validé en staging

2. Règles de résolution

FICHIER NOUVEAUPrincipe
mémo
Résolution d'un fichier en conflit (IntelliJ : Git > Resolve conflicts, ou à la main) :
  - "ours"   = develop-omega (nos devs : console agences/zones/GAB, dashboard GDF, Angular 17 + MF host)
  - "theirs" = origin/develop (les autres équipes : DC, Mainlevée, recherche users)
Jamais "accept ours/theirs" en bloc sur un fichier partagé : on garde les deux apports.
Après chaque fichier : npx ng build jusqu'à vert, puis git add <fichier>.
FichierRésolution
package.jsonGarder nos versions Angular / ngx-build-plus / module-federation 17 ; ajouter les dépendances nouvelles de develop (librairies DC / Mainlevée). Si develop a monté une lib qu'on a aussi, prendre la plus haute compatible 17.
package-lock.jsongit checkout --ours package-lock.json puis, après package.json résolu : npm install → commit du lock régénéré. Jamais d'édition manuelle.
angular.json, webpack.config.js, tsconfig*.jsonGarder notre config (builder ngx-build-plus, extraWebpackConfig, MF). Reprendre de develop uniquement un nouvel asset / style / projet déclaré.
src/app/app.module.ts, app-routing.module.tsGarder les deux : nos routes /admin/** (console) et /portail (remote MF, guard) + les nouvelles routes/modules develop (DC, Mainlevée). Vérifier qu'aucun module n'est importé deux fois et l'ordre des routes (wildcard ** en dernier).
src/app/console/**Normalement à nous seuls. Si develop a touché console.module.ts / console-routing.module.ts, garder nos routes agence, parametres/gab-hors-site + les leurs.
shared/interfaces/*.interface.ts, enum TS PermissionGarder les deux : nos GDF_*, AgenceDTO étendu (zoneDistribution, prestataire, coutDeplacement), GabHorsSite* + leurs DC_* / MLCHAB_*. Aucune valeur en double (le build TS le refuse).
core/services/** (auth, organization, distributor, gab)Garder les deux. Sur AuthService / CredentialsInterceptor : base develop, réappliquer notre logique MF (contexte porté par le shell, LoginGuard du remote désactivé).
layouts/side-menu, dashboard.component.*Garder les deux entrées de menu / cartes : nos cartes Dérogation + Gestion des fonds conditionnées par permission (checkCardPermissions), leurs cartes DC / Mainlevée. Même pattern *ngIf hasPermission([...]).
environments/*.ts, proxy.config.jsonGarder les nôtres (gateway 9090, consoleApiV1, /cash → 8300, mockAuthEnabled) + ajouter les clés nouvelles de develop. Les URLs DMZR (prod/staging) viennent du tech lead, pas de ce merge.
src/assets/mf.manifest.json, main.ts, bootstrap.tsNôtres (MF host). Develop ne doit pas les avoir.
.gitlab-ci.yml, sonar-project.properties, Dockerfile, nginx.confVersion develop (pipeline du tech lead).
*.spec.tsGarder les deux ; une spec develop qui casse sur Angular 17 → adapter (TestBed, HttpClientTestingModule → provideHttpClientTesting si déjà migré chez nous).
