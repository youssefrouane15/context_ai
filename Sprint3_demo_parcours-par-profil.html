Parcours 1 — Directeur d'agence (j43709, agence X)

Le DA ouvre la démo : il porte tout le cycle de vie côté agence, dans l'ordre du processus. Chaque étape s'enchaîne sur la précédente : ne saute pas d'étape, c'est le séquencement qui est démontré.

1.1Arrivée depuis le portail

Ce que tu fais
  • Portail (4200) : page de connexion mock, uid j43709.
  • Dashboard : la carte « Gestion des fonds » est visible ; clique dessus.
Ce que le métier voit
  • Redirection vers Gestion des fonds (4201) sur l'écran Nouvelle Demande, sans nouvelle connexion.
  • Bandeau haut : prénom + NOM du DA et son profil « Directeur d'agence ».
  • Menu gauche : « Réseau Agence » + code et nom de l'agence X ; entrées Nouvelle Demande et Historique Demandes ; pas d'entrée Caisse Centrale.
Contrôle technique (pour moi)
  • Réseau : GET …/users/me 200, puis POST …/cash/init 201 (un brouillon est créé à l'ouverture).
  • Camunda : nouvelle instance, Task_InitierDemande terminée, tâche active Task_SoumettreDemande assignee j43709.

1.2Contrôles de saisie

Ce que tu fais
  • Clique Soumettre sur le formulaire vide.
  • Saisis une quantité négative dans Alimentation Caisse, re-soumets.
  • Commande Devises : essaie d'ajouter une ligne sans devise.
Ce que le métier voit
  • Message « formulaire vide », rien n'est envoyé.
  • Message « corriger les champs » sur le champ en erreur.
  • Le bouton Ajouter reste inactif tant que devise et montant ne sont pas renseignés.
Contrôle technique (pour moi)
  • Aucun PUT ni /submit dans le Réseau ; le jeton reste sur Task_SoumettreDemande.

1.3Création et soumission d'une demande complète (demande n°1, urgente)

Ce que tu fais
  • Alimentation Caisse : 10 × 200 MAD ; GAB : une cassette ; Commande Devises : EUR ; Ramassage : MAD ; un commentaire ; coche DEMANDE URGENTE.
  • Vérifie les totaux affichés (Total saisi, Total GAB) puis Soumettre.
Ce que le métier voit
  • Message de succès, retour sur l'historique : la demande n°1 apparaît avec le statut Soumise et le badge urgent.
Contrôle technique (pour moi)
  • Réseau : PUT …/cash/{id} puis PATCH …/cash/{id}/submit, réponses 200.
  • Base : request_status = SUBMITTED, submitted_at posé, urgent = true, photo de l'agence remplie (agence_nom, zone_code, prestataire).
  • Camunda : Task_SoumettreDemande puis Task_InitialiserDemande (worker) terminées ; tâche active Task_TraitementCaisseCentrale ; variables urgent=true, typeDemande=AGENCE.

1.4Consultation de la demande soumise

Ce que tu fais
  • Historique → clique la demande n°1.
Ce que le métier voit
  • En-tête : chip Soumise, « Demande Réf RT-… », « Soumise le … par j43709 », badge urgent.
  • Champs en lecture seule, montants et commentaire identiques à la saisie.
  • Boutons : Retour, Modifier la demande, Annuler la demande. Pas de Soumettre.
Contrôle technique (pour moi)
  • Aucun changement moteur : la tâche Caisse Centrale reste active.

1.5Modification enregistrée (verrou pris puis rendu)

Ce que tu fais
  • Modifier la demande : le bouton affiche « Verrouillage… » puis l'écran passe en modification.
  • Change une quantité, le commentaire, décoche URGENTE, Enregistrer.
Ce que le métier voit
  • Retour en consultation avec les nouvelles valeurs, chip Soumise, badge urgent disparu.
Contrôle technique (pour moi)
  • Pendant l'édition : statut IN_MODIFICATION, locked_by = j43709 ; Camunda : tâche active Task_ModifierDemande, plus aucune tâche Caisse Centrale (la Caisse Centrale ne peut pas traiter pendant ce temps : voir 3.5).
  • Après : Task_AppliquerModification terminée, nouvelle Task_TraitementCaisseCentrale ; modificationConfirmee=true, urgent=false.

1.6Modification abandonnée et réinitialisation d'une section

Ce que tu fais
  • Modifier la demande → clique « Réinitialiser l'alimentation caisse » puis change une ligne GAB → Annuler.
Ce que le métier voit
  • La section réinitialisée repasse à 0 pendant l'édition, les autres ne bougent pas.
  • Après Annuler : retour en consultation avec les valeurs d'avant, rien n'a été enregistré.
Contrôle technique (pour moi)
  • Camunda : Task_ModifierDemande complétée avec modificationConfirmee=false, nouvelle Task_TraitementCaisseCentrale.

1.7Brouillon : quitter, reprendre, soumettre depuis la consultation (demande n°2, non urgente)

Ce que tu fais
  • Menu Nouvelle Demande : saisis une seule ligne GAB, ne coche pas URGENTE, puis Retour au listing sans soumettre.
  • Historique : filtre Statut = Tous → ouvre ce brouillon.
  • Modifier la demande (pas de « Verrouillage… » sur un brouillon), ajoute une ligne Caisse, Enregistrer, puis Soumettre depuis la consultation.
Ce que le métier voit
  • Brouillon : chip Initiée, boutons Modifier, Annuler et Soumettre.
  • Après Soumettre : chip Soumise. La demande n°2 servira à la Caisse Centrale (annulation) et aux filtres.
Contrôle technique (pour moi)
  • Aucun passage par Task_ModifierDemande pour un brouillon ; Task_SoumettreDemande complétée à la soumission.

1.8Annulation par l'agence (demande n°3)

Ce que tu fais
  • Crée et soumets une demande n°3 (n'importe quel contenu).
  • Consultation → Annuler la demande : motif de 5 caractères → refusé ; motif ≥ 10 caractères → confirmer.
Ce que le métier voit
  • Chip Annulée (Agence), motif affiché dans l'en-tête, plus aucun bouton d'action.
  • Historique : la demande n°3 est annulée.
Contrôle technique (pour moi)
  • Base : CANCELLED, cancellation_origin = CREATEUR, motif.
  • Camunda : message msgAnnulerDemande corrélé, worker gdf-annuler-demande, instance terminée.

1.9Historique agence : uniquement mon agence

Ce que tu fais
  • Menu Historique Demandes ; joue les filtres période, type, statut, recherche par référence ; Export CSV.
Ce que le métier voit
  • Uniquement les demandes de l'agence X (n°1 soumise, n°2 soumise, n°3 annulée, brouillons éventuels). Le filtre agence n'a que X.
Contrôle technique (pour moi)
  • Réseau : GET …/cash?… sans paramètre agence côté front : le filtrage est fait par le back à partir de l'identité (B2).

1.10Ce que le DA ne peut pas faire

Ce que tu fais
  • Tape /caisse-centrale dans l'URL.
  • Tape /consultation/<id d'une demande d'une autre agence> (à préparer avec le Chef de caisse en agence Y, parcours 2.4).
Ce que le métier voit
  • /caisse-centrale : zone centrale vide, pas d'entrée dans le menu.
  • Demande d'une autre agence : message d'erreur, aucune donnée affichée.
Contrôle technique (pour moi)
  • Garde de route toutesAgences côté front ; 403 du back sur la demande d'une autre agence.

1.11Retour au portail

Ce que tu fais
  • Bouton Accueil du bandeau haut.
Ce que le métier voit
  • Retour sur le dashboard du portail, toujours connecté.
Contrôle technique (pour moi)
  • environment.portailUrl.

Parcours 2 — Chef de caisse (j08221, agence X)

Mêmes habilitations que le DA. Le parcours montre deux choses : il voit et agit sur les demandes de son agence même s'il ne les a pas créées, et deux agents ne peuvent pas modifier la même demande en même temps. Fenêtre privée pour garder le DA connecté à côté.

2.1Arrivée et périmètre

Ce que tu fais
  • Fenêtre privée : portail → uid j08221 → carte Gestion des fonds.
Ce que le métier voit
  • Même menu que le DA (Réseau Agence, agence X, Nouvelle Demande, Historique).
  • Historique : les demandes n°1 et n°2 créées par le DA sont visibles avec leurs boutons : le périmètre est l'agence, pas l'auteur.

2.2Verrou concurrent sur la demande n°1

Ce que tu fais
  • DA (fenêtre normale) : consultation n°1 → Modifier la demande, reste sur l'écran.
  • Chef de caisse : ouvre la demande n°1 en consultation, puis force l'URL /modification/<id>.
  • DA : Enregistrer. Chef de caisse : recharge.
Ce que le métier voit
  • Chef de caisse : chip En modification, mention « verrouillée par j43709 », pas de bouton Modifier ; l'URL forcée renvoie en consultation avec un avertissement.
  • Après l'enregistrement du DA : chip Soumise, le bouton Modifier réapparaît pour le Chef de caisse.
Contrôle technique (pour moi)
  • Une seule Task_ModifierDemande, assignee j43709 ; le back répond 403 « verrouillée par un autre agent » si on force.

2.3Expiration du verrou (optionnel, 2 min)

Ce que tu fais
  • Uniquement si gdf.verrou-modification-duree: PT2M a été posé avant la démo : Chef de caisse → Modifier la demande n°2 → ferme l'onglet sans enregistrer. Attends 2 min 30, le DA recharge la consultation.
Ce que le métier voit
  • DA : chip Soumise, bouton Modifier de nouveau disponible, valeurs inchangées.
Contrôle technique (pour moi)
  • Boundary timer du verrou déclenché, Task_AppliquerModification sans modificationConfirmee, nouvelle tâche Caisse Centrale. Remettre PT30M ensuite.

2.4Cloisonnement entre agences (à préparer avant la démo)

Ce que tu fais
  • Avant la démo, si tu veux le montrer : rattache un troisième utilisateur agence à l'agence Y (annexe A) et crée une demande avec lui.
Ce que le métier voit
  • Le Chef de caisse de X ne voit pas cette demande dans son historique et ne peut pas l'ouvrir par l'URL (1.10).
Contrôle technique (pour moi)
  • branch_code = Y sur cette demande ; 403 du back pour X.

Parcours 3 — Caisse Centrale ({{UID_CC}})

La Caisse Centrale voit toutes les agences et décide. Le parcours enchaîne : arrivée, lecture du listing, filtres, décision « Traiter » sur la demande n°1, décision « Annuler » sur la demande n°2, et ce qu'elle ne peut pas faire. Les demandes n°1 et n°2 doivent être Soumises (parcours 1 terminé, aucune modification en cours).

3.1Arrivée : page d'accueil dédiée

Ce que tu fais
  • Fenêtre privée : portail → uid {{UID_CC}} → carte Gestion des fonds.
Ce que le métier voit
  • Arrivée directement sur le listing Caisse Centrale (pas sur Nouvelle Demande).
  • Menu : « Caisse Centrale » + libellé du profil ; entrées Historique Demandes et Caisse Centrale ; pas de Nouvelle Demande.
  • Bandeau haut : nom et profil « Caisse Centrale ».
Contrôle technique (pour moi)
  • Route '' → accueilParProfil → /caisse-centrale ; habilitations().creer = false.

3.2Lecture du listing

Ce que tu fais
  • Observe la page sans toucher aux filtres.
Ce que le métier voit
  • 4 cartes KPI en haut (valeurs de maquette : 14 / 3 / 28 / 10).
  • Filtres : Demandes urgentes, Statut (En attente par défaut), Transporteur, Zone, Recherche.
  • Tableau : Référence, Urgence, Agence émettrice & zone, Transporteur, Heure demande, Contenu, Statut, Actions.
  • Les demandes n°1 (urgente, décochée en 1.5 donc non urgente maintenant) et n°2 sont là : code + nom de l'agence X, uid du demandeur, zone, badge transporteur (Brink's noir / G4S rouge), chips de contenu, chip En attente, boutons Détail / Traiter / Annuler.
  • La demande n°3 (annulée agence) n'apparaît pas en « En attente ».
Contrôle technique (pour moi)
  • Réseau : GET …/cash?statut=SUBMITTED&page=0&size=20 et GET …/users/orga/agences 200 (listes Transporteur / Zone alimentées).
  • Les colonnes agence / zone / transporteur viennent de la photo figée sur la demande (V4).

3.3Filtres

Ce que tu fais
  • Avant : le DA crée et soumet une demande n°4 urgente (n°1 n'est plus urgente).
  • Coche « Demandes urgentes uniquement » ; puis Transporteur = celui de X, puis l'autre transporteur ; Zone = celle de X, puis une autre ; Statut = Annulée ; Recherche = fin de la référence de n°2.
Ce que le métier voit
  • Urgentes : seule n°4 reste. Transporteur / Zone de X : toutes reviennent ; autre valeur : « Aucune demande ». Statut Annulée : n°3 avec chip Annulée (Agence). Recherche : une seule ligne.
  • La pagination revient en page 1 à chaque changement de filtre.
Contrôle technique (pour moi)
  • Chaque filtre est un paramètre d'URL (urgent, prestataire, zone, statut, recherche) : le filtrage est fait par le serveur, pas dans le navigateur.

3.4Détail = consultation en lecture seule

Ce que tu fais
  • Détail sur la demande n°1 ; puis retour arrière du navigateur.
Ce que le métier voit
  • Écran de consultation complet, bandeau « Consultation seule : la décision se prend depuis le listing Caisse Centrale », aucun bouton Modifier / Annuler / Soumettre.
  • Retour : le listing garde ses filtres.
Contrôle technique (pour moi)
  • calculerCapacites : visible = toutesAgences, ouverte exige une demande de sa propre agence.

3.5Séquencement : pas de décision pendant une modification agence

Ce que tu fais
  • DA : Modifier la demande n°1, reste en édition. Caisse Centrale : Statut = En modification.
  • DA : Annuler l'édition. Caisse Centrale : Statut = En attente.
Ce que le métier voit
  • En modification : n°1 apparaît avec la chip En modification et sans boutons Traiter / Annuler.
  • Après : n°1 revient en attente avec ses boutons.
Contrôle technique (pour moi)
  • Camunda : pendant l'édition, aucune Task_TraitementCaisseCentrale active ; elle est recréée après Task_AppliquerModification.

3.6Décision Traiter (demande n°1)

Ce que tu fais
  • Traiter sur n°1 → panneau « Traiter la demande RT-… ? » → Confirmer le traitement.
  • Statut = Traitée.
  • DA (fenêtre normale) : consultation de n°1.
Ce que le métier voit
  • Message « le statut sera mis à jour dans quelques secondes », la ligne quitte « En attente » ; en « Traitée » : chip Traitée, plus de boutons de décision.
  • DA : « Traitée le … par la Caisse Centrale », lecture seule, plus de Modifier / Annuler.
Contrôle technique (pour moi)
  • Base : VALIDATED. Camunda : Task_TraitementCaisseCentrale complétée avec decisionCaisseCentrale=TRAITEE, worker gdf-cloturer-demande, instance terminée.

3.7Décision Annuler avec motif (demande n°2)

Ce que tu fais
  • Annuler sur n°2 → motif de 5 caractères → bouton inactif ; motif ≥ 10 caractères → Confirmer l'annulation.
  • Statut = Annulée. DA : consultation de n°2.
Ce que le métier voit
  • Chip Annulée (Caisse Centrale) ; DA : motif dans l'en-tête, aucun bouton.
  • À côté, n°3 reste Annulée (Agence) : deux origines distinctes visibles dans le même filtre.
Contrôle technique (pour moi)
  • Base : CANCELLED, cancellation_origin = CAISSE_CENTRALE. Camunda : Task_TraitementCaisseCentrale complétée avec ANNULEE, worker gdf-annuler-demande, instance terminée.

3.8Historique toutes agences

Ce que tu fais
  • Menu Historique Demandes.
Ce que le métier voit
  • Toutes les agences ; le filtre agence propose toutes les agences.
Contrôle technique (pour moi)
  • Contexte toutesAgences = true : pas de filtre agence imposé par le back.

3.9Ce que la Caisse Centrale ne peut pas faire

Ce que tu fais
  • Tape / ou /nouvelle-demande dans l'URL.
Ce que le métier voit
  • Renvoi sur le listing Caisse Centrale ; aucun brouillon n'est créé (l'historique n'a pas de nouvelle ligne).
Contrôle technique (pour moi)
  • Pas de POST …/cash/init dans le Réseau.

Parcours 4 — Support ({{UID_SUPPORT}})

Le Support voit tout et ne touche à rien. C'est le parcours le plus court : il ferme la démo sur les habilitations.

4.1Arrivée

Ce que tu fais
  • Fenêtre privée : portail → uid {{UID_SUPPORT}} → carte Gestion des fonds.
Ce que le métier voit
  • Arrivée sur le listing Caisse Centrale ; menu Historique + Caisse Centrale, pas de Nouvelle Demande ; bandeau avec le profil Support.

4.2Listing en lecture seule

Ce que tu fais
  • Statut = En attente, puis Tous les statuts.
Ce que le métier voit
  • Mêmes lignes que la Caisse Centrale, filtres opérationnels, mais uniquement le bouton Détail : pas de Traiter, pas d'Annuler.

Ce que tu fais

Ce que le métier voit

  • Historique toutes agences, export CSV possible.

Ce que tu fais
  • Tape /, /modification/<id> dans l'URL.
Ce que le métier voit
  • Renvoi sur le listing ; aucune modification, aucun brouillon.

-- Contrôle : permissions GDF par persona (la matrice §6 en dépend)
SELECT u.uid, p.code AS profil, o.code AS agence,
       string_agg(DISTINCT rp.permission, ', ' ORDER BY rp.permission) AS permissions
FROM users u JOIN hab_profiles p ON p.id = u.profile_id
LEFT JOIN orga_unit o ON o.id = u.organization_unit_id
JOIN hab_profile_role pr ON pr.profile_id = p.id
JOIN hab_role_permission rp ON rp.role_id = pr.role_id AND rp.permission LIKE 'GDF_%'
