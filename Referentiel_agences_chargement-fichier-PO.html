0. Principe

Le fichier du PO est la source de vérité ; on ne le retape pas en SQL à la main. Il est chargé tel quel dans une table de staging, contrôlé, puis transformé en une migration Flyway V18 générée automatiquement — c'est cette V18 qui met la base à jour, en local comme en prod (même convention que V12/V13, qui étaient déjà des corrections de données).

Colonne ExcelCible (schéma qf_admin)Règle
CODE AGENCEorga_unit.code (type AGENCE)clé de jointure — jamais modifiée
Agenceorga_unit.namecontrôle d'écart seulement, pas d'écrasement
REGION/ZONEzone_distribution → orga_unit.zone_distribution_idzone créée si absente (code = libellé du fichier en majuscules)
PRESTATAIREorga_unit.prestataireCHECK BRINKS / G4S — valeurs du fichier déjà conformes
PUorga_unit.cout_deplacement numeric(12,2)171,73 → 171.73

Ordre : 1 contrôle du schéma → 2 Excel → CSV → 3 staging + import → 4 nettoyage et contrôles → 5 écarts (à remettre au PO) → 6 zones provisoires → 7 génération de V18 → 8 démarrage d'utilisateurs-ci → 9 vérification → 10 nettoyage → 11 livraison. Tout le SQL s'exécute dans pgAdmin → base utilisateurs-ci → Query Tool (F5 pour exécuter).

Deux points à dire au PO : les UPDATE SQL ne passent pas par l'API, donc pas de ligne d'audit Envers dans orga_unit_aud ; et les demandes déjà créées gardent leur photo agence/zone/prestataire figée (retail.cash_request) — seules les nouvelles demandes prennent les valeurs du fichier.

3. Table de staging et import

FICHIER NOUVEAU01-staging.sql
pgAdmin → Query Tool
set search_path to qf_admin;

-- Table de staging = copie brute du fichier Excel, tout en texte (aucune conversion à l'import).
drop table if exists stg_referentiel_agence;
create table stg_referentiel_agence (
    agence       text,   -- colonne A : Agence
    code_agence  text,   -- colonne B : CODE AGENCE
    zone         text,   -- colonne C : REGION/ZONE
    prestataire  text,   -- colonne D : PRESTATAIRE
    pu           text    -- colonne E : PU (coût de déplacement, virgule décimale)
);

Import dans pgAdmin : arbre de gauche → base → Schemas → qf_admin → Tables → clic droit sur stg_referentiel_agence (F5 sur « Tables » si elle n'apparaît pas) → Import/Export Data…

  • Onglet General : Import/Export = Import ; Filename = C:\dev\referentiel\referentiel_agences.csv ; Format = csv ; Encoding = UTF8.
  • Onglet Options : Header = ON ; Delimiter = ; (ou , selon le §2.4) ; Quote = " ; Escape = " ; NULL Strings vide.
  • Onglet Columns : laisser les 5 colonnes dans l'ordre agence, code_agence, zone, prestataire, pu (= ordre des colonnes Excel A→E).
  • OK → notification « Import — Successfully completed ».

Erreur « extra data after last expected column » = mauvais séparateur, refais avec l'autre. Erreur « invalid byte sequence for encoding UTF8 » = le CSV n'est pas en UTF-8 : refais le §2.3 en choisissant bien « CSV UTF-8 ».

4. Nettoyage et contrôles de la staging

FICHIER NOUVEAU02-nettoyage-controles.sql
pgAdmin → Query Tool (exécuter tout, lire les résultats onglet par onglet)

C = nombre de lignes de l'Excel ; D, E, F doivent être vides (sinon corriger dans la staging : update stg_referentiel_agence set prestataire = 'BRINKS' where code_agence = '…'). Si les codes en base ont des zéros devant (§1 requête 4), ajoute , code_agence = lpad(code_agence, 5, '0') dans l'UPDATE A.

set search_path to qf_admin;

-- A. Nettoyage (espaces, casse) — idempotent
update stg_referentiel_agence set
    agence      = trim(agence),
    code_agence = trim(code_agence),
    zone        = upper(trim(zone)),
    prestataire = upper(replace(replace(trim(prestataire), '''', ''), ' ', '')),   -- "Brink's" → BRINKS
    pu          = replace(trim(pu), ' ', '');

-- B. Lignes vides éventuelles (fin de feuille)
delete from stg_referentiel_agence where coalesce(code_agence, '') = '';

-- C. Volume : doit être égal au nombre de lignes de l'Excel (hors en-tête)
select count(*) as lignes from stg_referentiel_agence;

-- D. Codes en double dans le fichier → attendu : 0 ligne
select code_agence, count(*) from stg_referentiel_agence group by code_agence having count(*) > 1;

-- E. Prestataire hors BRINKS / G4S → attendu : 0 ligne (sinon la CHECK de orga_unit refusera l'update)
select * from stg_referentiel_agence where prestataire not in ('BRINKS', 'G4S');

-- F. PU non numérique → attendu : 0 ligne
select * from stg_referentiel_agence where pu !~ '^[0-9]+([,.][0-9]+)?$';

-- G. Zones distinctes du fichier (c'est la liste qui sera créée dans zone_distribution si absente)
select zone, count(*) as agences from stg_referentiel_agence group by zone order by zone;

5. Écarts fichier ↔ base (à remettre au PO)

FICHIER NOUVEAU03-ecarts.sql
pgAdmin → Query Tool

A = agences du fichier inconnues en base : le script ne les crée pas (il leur faut un groupe parent dans orga_unit) → liste à renvoyer au PO. B = agences en base hors fichier : resteront sans zone / prestataire / coût. Les résultats se copient directement dans un mail (clic droit sur la grille → Copy).

set search_path to qf_admin;

-- A. Agences du fichier ABSENTES de la base → à montrer au PO (non créées par le script : il leur faut un groupe parent)
select s.code_agence, s.agence, s.zone, s.prestataire, s.pu
from stg_referentiel_agence s
left join orga_unit o on o.type = 'AGENCE' and o.code = s.code_agence
where o.id is null
order by s.code_agence;

-- B. Agences en base ABSENTES du fichier → resteront sans zone / prestataire / coût
select o.code, o.name, o.actif
from orga_unit o
left join stg_referentiel_agence s on s.code_agence = o.code
where o.type = 'AGENCE' and s.code_agence is null
order by o.code;

-- C. Libellés qui diffèrent (information : le script ne touche pas au nom)
select o.code, o.name as nom_base, s.agence as nom_fichier
from orga_unit o
join stg_referentiel_agence s on s.code_agence = o.code
where o.type = 'AGENCE' and upper(trim(o.name)) <> s.agence
order by o.code;

-- D. Synthèse
select
  (select count(*) from stg_referentiel_agence) as lignes_fichier,
  (select count(*) from stg_referentiel_agence s join orga_unit o on o.type='AGENCE' and o.code = s.code_agence) as agences_mises_a_jour,
  (select count(*) from stg_referentiel_agence s left join orga_unit o on o.type='AGENCE' and o.code = s.code_agence where o.id is null) as agences_inconnues,
  (select count(distinct s.zone) from stg_referentiel_agence s left join zone_distribution z on z.code = s.zone where z.id is null) as zones_a_creer;

6. Zones provisoires de V14

FICHIER NOUVEAU02bis-zones-provisoires.sql
pgAdmin → Query Tool

Les zones CASA / RABAT seedées en V14 venaient de la maquette, pas d'un référentiel. Si la requête montre CASA avec des agences rattachées, l'UPDATE la renomme en CASABLANCA (le code du fichier) pour éviter deux zones Casablanca ; l'id ne bouge pas, les agences suivent. Cette ligne est reprise en tête de V18 (§7) pour que prod fasse pareil.

set search_path to qf_admin;

-- Les zones seedées en V14 (CASA « Zone Casablanca », RABAT « Zone Rabat-Salé ») étaient provisoires (valeurs de la maquette 268).
-- Le fichier du PO est maintenant la référence : ses libellés de zone (CASABLANCA, RABAT, AGADIR…) deviennent les codes.
-- Sans cette étape, V18 créerait CASABLANCA à côté de CASA → doublon fonctionnel. À exécuter AVANT de générer V18, puis à recopier en tête de V18 (§6).

-- Quelles zones existantes ne sont pas dans le fichier, et combien d'agences les utilisent déjà ?
select z.id, z.code, z.nom, count(o.id) as agences_rattachees
from zone_distribution z
left join orga_unit o on o.zone_distribution_id = z.id
left join stg_referentiel_agence s on s.zone = z.code
where s.zone is null
group by z.id, z.code, z.nom order by z.code;

-- Décision proposée : renommer le code de la zone provisoire vers le libellé du fichier (les agences déjà rattachées suivent, l'id ne change pas).
-- (Adapter la paire CASA → CASABLANCA selon le résultat ci-dessus ; RABAT existe déjà sous le même code.)
update zone_distribution set code = 'CASABLANCA', updated_at = now()
where code = 'CASA' and not exists (select 1 from zone_distribution where code = 'CASABLANCA');

-- Résultat = UNE cellule de texte : clic sur la cellule → Ctrl+C → coller tel quel dans le fichier V18 (sans l'en-tête de colonne « v18 »).
select
'-- V18 — Référentiel agences (fichier PO Zones_Agences_Transporteurs_PU) : zone de distribution, prestataire, coût de déplacement.
-- Généré depuis la table de staging le ' || to_char(now(), 'DD/MM/YYYY') || ' — ' || count(*) || ' agences. Idempotent : rejouable sans effet de bord.

-- 0. Zone provisoire de V14 alignée sur le code du fichier (voir 02bis — supprimer cette ligne si non appliquée en local)
update zone_distribution set code = ''CASABLANCA'', updated_at = now()
where code = ''CASA'' and not exists (select 1 from zone_distribution where code = ''CASABLANCA'');

create temp table tmp_ref_agence (code_agence text, agence text, zone text, prestataire text, pu numeric(12,2)) on commit drop;

insert into tmp_ref_agence (code_agence, agence, zone, prestataire, pu) values
' || string_agg(format('(%L, %L, %L, %L, %s)', code_agence, agence, zone, prestataire, replace(pu, ',', '.')), E',\n' order by code_agence) || ';

-- 1. Zones de distribution manquantes
insert into zone_distribution (code, nom, actif, created_at, updated_at)
select distinct t.zone, initcap(t.zone), true, now(), now()
from tmp_ref_agence t
left join zone_distribution z on z.code = t.zone
where z.id is null;

-- 2. Agences : zone, prestataire, coût (jointure sur le code agence ; les codes inconnus en base sont ignorés — liste remise au PO)
update orga_unit o
set zone_distribution_id = z.id,
    prestataire          = t.prestataire,
    cout_deplacement     = t.pu,
    updated_at           = now()
from tmp_ref_agence t
join zone_distribution z on z.code = t.zone
where o.type = ''AGENCE'' and o.code = t.code_agence;
' as v18
from stg_referentiel_agence;

9. Vérification

FICHIER NOUVEAU05-verification.sql
pgAdmin → Query Tool

Attendus : V18 success = true ; agences_sans_zone = nombre de lignes de 03-B (agences hors fichier) ; contrôle croisé = 0 ligne. Côté console (portail-ci, onglet Agences) : colonnes Zone Transporteur / Prestataire / Coût remplies, ex. AGADIR AL MENZEH → Agadir / BRINKS / 171,73 MAD.

set search_path to qf_admin;

-- Après démarrage d'utilisateurs-ci (V18 appliquée)
select version, description, success, installed_on from flyway_schema_history order by installed_rank desc limit 3;

-- Agences : tout le fichier doit être reporté
select o.code, o.name, z.code as zone, o.prestataire, o.cout_deplacement
from orga_unit o
left join zone_distribution z on z.id = o.zone_distribution_id
where o.type = 'AGENCE'
order by o.code;

-- Compteurs : agences_sans_zone = agences absentes du fichier (liste 03-B), rien d'autre
select
  count(*) filter (where zone_distribution_id is null) as agences_sans_zone,
  count(*) filter (where prestataire is null)          as agences_sans_prestataire,
  count(*) filter (where cout_deplacement is null)     as agences_sans_cout,
  count(*)                                             as total
from orga_unit where type = 'AGENCE';

-- Contrôle croisé fichier ↔ base : attendu 0 ligne
select s.code_agence, s.zone, z.code as zone_base, s.prestataire, o.prestataire as prestataire_base, s.pu, o.cout_deplacement
from stg_referentiel_agence s
join orga_unit o on o.type = 'AGENCE' and o.code = s.code_agence
left join zone_distribution z on z.id = o.zone_distribution_id
where z.code is distinct from s.zone
   or o.prestataire is distinct from s.prestataire
   or o.cout_deplacement is distinct from replace(s.pu, ',', '.')::numeric;

-- Zones créées
select * from zone_distribution order by code;
