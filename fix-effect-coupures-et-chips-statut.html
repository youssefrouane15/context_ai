Fix — Coupures effacées au switch Historique ↔ Nouvelle demande + chips statut sans couleur

Cause racine : un effect monolithique qui reconstruit les FormArrays à chaque émission de signal. Fix : séparation en deux effects + synchronisation idempotente par comparaison de denominationCode. Bonus : chips statut alignées template ↔ SCSS avec SUBMITTED et VALIDATED.

02/09/2026 · fund-management-front (retail) · 2 fichiers touchés

1Le bug expliqué simplement

Un effect Angular re-tourne à chaque changement de n'importe quel signal lu dedans. Ton effect du constructeur lit devises(), coupuresGab() et coupuresCaisse(), et à chaque tour il fait clear() puis push(...) sur les FormArrays.

PREMIÈRE VISITE (store vide) RETOUR DEPUIS L'HISTORIQUE (store déjà rempli — providedIn: 'root') ──────────────────────────── ──────────────────────────────────────────────── effect → store vide → rien à construire effect → construit les lignes IMMÉDIATEMENT loadCoupures/loadDevises terminent ngOnInit → loadCoupures() + loadDevises() relancés effect → construit les lignes tu tapes tes quantités... ✍ TU TAPES APRÈS → rien ne t'efface ✔ les appels reviennent (500 → fallback mock) chaque set() = NOUVELLE référence de tableau effect re-tourne → clear() → quantités = 0 ✘ submit → « au moins un type (gab, etc.) » ✘
Aggravant : comme devises() est lu dans le même effect, même le simple rechargement des devises efface les coupures saisies. Trois signaux, un seul effect = trois occasions d'écraser la saisie.
Le fix clean : un effect = une responsabilité. Effet 1 pour les devises (ne touche jamais aux coupures). Effet 2 pour les coupures, avec une synchronisation idempotente : on ne reconstruit que si la liste des denominationCode a réellement changé. Référentiel identique → aucun clear() → la saisie survit. C'est le même principe que le fix du rebond demandeCreee : un signal consommé sans discernement provoque des effets de bord non voulus.

src\app\features\fund-management\presenter\pages\fund-management\fund-management.component.tsÀ AJOUTER — section « Helpers privés », juste au-dessus de creerLigneCoupure
  /**
   * Aligne un FormArray de coupures sur le référentiel reçu.
   * Si les codes sont identiques (même liste, même ordre), on ne touche à rien :
   * les quantités déjà saisies sont préservées. Sinon on reconstruit.
   * Retourne true si une reconstruction a eu lieu.
   */
  private synchroniserCoupures(tableau: FormArray, coupures: Denomination[]): boolean {
    const codesActuels = tableau.controls.map(l => l.get('code')?.value).join('|');
    const codesCibles = coupures.map(c => c.denominationCode).join('|');

    if (codesActuels === codesCibles) {
      return false;
    }

    tableau.clear();
    coupures.forEach(c => tableau.push(this.creerLigneCoupure(c)));
    return true;
  }

Rechargement des devisesEffaçait aussi les coupures (même effect)Effet 1 isolé : ne touche jamais aux FormArrays de coupures
Référentiel réellement modifié (nouvelle coupure en base)—Codes différents → reconstruction propre + repartirCoupuresCaisse()
