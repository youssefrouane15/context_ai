0. Cause réelle et principe du fix

Ce que montrent tes captures. En mode mock, la « session » n'est pas en base : login() construit la map request (l.56-64) mais ne l'envoie jamais (webClient et urlsProperties : 1 usage chacun = le constructeur). La session, c'est le JWT dans le cookie QF_MOCK_SESSION (HttpOnly, Path=/, SameSite=Lax, 1 h) que QfTokenRelayFilter relaie en Bearer. Et il n'existe aucun endpoint de logout en mock : seul QfLogoutHandler (oauth) existe.

Pourquoi /login → dashboard en DMZR. Le portail v4 recharge bien la page, mais le cookie est HttpOnly : le JS ne peut pas le supprimer, et en DMZR portail et gateway sont sur le même hôte → le navigateur le renvoie au /me du rechargement → 200 → le shell se croit connecté → dashboard. En local (4200 ≠ 9090) le cookie posé par 9090 n'était simplement pas partagé de la même façon, d'où le « ça marchait ».

Fix. La session s'invalide là où elle vit : (1) la gateway expose POST /mock-auth/logout qui renvoie le même cookie avec Max-Age=0 (le navigateur ne remplace un cookie que si nom + path correspondent, d'où la copie exacte des attributs du login) ; (2) le portail attend cette réponse, puis nettoie et recharge. Pas d'appel à utilisateurs-ci en mock : il n'y a rien à supprimer côté serveur. /mock-auth/** est déjà permitAll et le controller a déjà @CrossOrigin(allowCredentials) : aucune config sécurité/CORS à toucher.

1. api-gateway-ci

À AJOUTERMockAuthController.java — endpoint /logout
api-gateway-ci\src\main\java\com\bnpparibas\irb\qlickflow\apigateway\security\mock\MockAuthController.java

Insérer entre login() et ping(). Les attributs sont volontairement identiques à ceux du cookie posé par login() (l.66-73). Si un jour login() passe secure(true) ou un domain, reporter la même valeur ici.

    // À AJOUTER après login() (ligne 76), avant /ping. Aucun import nouveau : PostMapping, ServerWebExchange,
    // ResponseCookie, ResponseEntity et Mono sont déjà importés pour login().
    @PostMapping("/logout")
    public Mono<ResponseEntity<Void>> logout(ServerWebExchange exchange) {
        // Le navigateur ne remplace un cookie que si (nom, domaine, path) sont identiques à ceux du login :
        // même nom (sessionCookieName) et même path("/"). Max-Age=0 → suppression immédiate.
        var expire = ResponseCookie.from(sessionCookieName, "")
                .httpOnly(true)
                .secure(false)
                .path("/")
                .sameSite("Lax")
                .maxAge(0)
                .build();
        exchange.getResponse().addCookie(expire);
        return Mono.just(ResponseEntity.noContent().build());
    }

package com.bnpparibas.irb.qlickflow.apigateway.security.mock;

import org.junit.jupiter.api.Test;
import org.springframework.http.HttpStatus;
import org.springframework.mock.http.server.reactive.MockServerHttpRequest;
import org.springframework.mock.web.server.MockServerWebExchange;

import java.time.Duration;

import static org.assertj.core.api.Assertions.assertThat;

class MockAuthControllerLogoutTest {

    @Test
    void logout_expireLeCookieDeSessionAvecLesAttributsDuLogin() {
        var controller = new MockAuthController(null, null, null, "QF_MOCK_SESSION");
        var exchange = MockServerWebExchange.from(MockServerHttpRequest.post("/mock-auth/logout"));

        var reponse = controller.logout(exchange).block();

        assertThat(reponse).isNotNull();
        assertThat(reponse.getStatusCode()).isEqualTo(HttpStatus.NO_CONTENT);
        var cookie = exchange.getResponse().getCookies().getFirst("QF_MOCK_SESSION");
        assertThat(cookie).isNotNull();
        assertThat(cookie.getValue()).isEmpty();
        assertThat(cookie.getMaxAge()).isEqualTo(Duration.ZERO);
        assertThat(cookie.getPath()).isEqualTo("/");
        assertThat(cookie.isHttpOnly()).isTrue();
        assertThat(cookie.getSameSite()).isEqualTo("Lax");
    }
}

2. portail-ci

ÉDITIONauth.service.ts — logout() devient asynchrone
portail-ci\src\app\core\services\auth\auth.service.ts

Remplace la méthode logout() v4. this.http et environment.gatewayUrl = le HttpClient et la base d'URL déjà utilisés par login() pour /mock-auth/login ; environment.mockAuthEnabled = le flag mock existant du portail. Garde les identifiants réels du fichier si les noms diffèrent — rien d'autre n'est à inventer.

import { firstValueFrom } from 'rxjs';   // à ajouter aux imports si absent

  /** Déconnexion : 1) la gateway expire le cookie de session, 2) nettoyage local, 3) rechargement complet. */
  async logout(): Promise<void> {
    await this.deconnecterGateway();
    this.nettoyerEtatLocal();
    // Une seule navigation « document » (hash routing DMZR : la query ?_= force le rechargement, puis Angular lit #/login).
    window.location.replace(environment.useHash
      ? `${window.location.origin}/?_=${Date.now()}#/login`
      : `${window.location.origin}/login`);
  }

  /**
   * La session vit dans la gateway (cookie HttpOnly QF_MOCK_SESSION, invisible au JS) : seule la gateway peut l'expirer.
   * On ATTEND sa réponse avant de recharger, sinon le /me du rechargement repart avec l'ancien cookie → dashboard.
   * mock  : POST /mock-auth/logout (MockAuthController)
   * oauth : POST /logout (Spring Security → QfLogoutHandler supprime la session dans utilisateurs-ci)
   */
  private async deconnecterGateway(): Promise<void> {
    const chemin = environment.mockAuthEnabled ? '/mock-auth/logout' : '/logout';
    try {
      await firstValueFrom(this.http.post<void>(`${environment.gatewayUrl}${chemin}`, null, { withCredentials: true }));
    } catch (e) {
      // Gateway injoignable (ou 302 oauth non suivi) : la session est de toute façon à expirer côté serveur,
      // on repart quand même de zéro côté client.
      console.warn('Déconnexion gateway impossible, rechargement quand même', e);
    }
  }

  private nettoyerEtatLocal(): void {
    try {
      this.menuModule.reinitialiser();   // AER_LM-336 : plus d'entrées de menu de l'utilisateur précédent
      sessionStorage.clear();
      Object.keys(localStorage).filter(k => k.startsWith('qf.')).forEach(k => localStorage.removeItem(k));
    } catch (e) {
      console.warn('Nettoyage local partiel', e);
    }
  }
ÉDITIONheader.component.ts — logout()
portail-ci\src\app\layouts\header\header.component.ts

void explicite : on ne veut pas attendre dans le composant, AuthService gère la suite (y compris le rechargement).

  logout() {
    // asynchrone : AuthService attend la gateway puis recharge la page sur /login
    void this.authService.logout();
  }
Ordre, et pourquoi il compte : await gateway → nettoyage local → replace. Si on recharge avant la réponse, le navigateur annule la requête logout en vol et le cookie survit. Si la gateway est injoignable, on recharge quand même (le catch) : l'utilisateur retombe sur le login avec un cookie encore valide 1 h max — comportement dégradé assumé, tracé en console.warn.
Mode oauth : même méthode, chemin /logout → Spring Security enchaîne QfLogoutHandler (DELETE /api/v1/internal/oauth-sessions/{uid}) et invalide la session ; la réponse (302 vers la page de fin de session) tombe dans le catch — sans importance, la session est déjà détruite. À recetter quand le dev-sso sera disponible.
