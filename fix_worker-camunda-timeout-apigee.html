Fix — worker Camunda coupé par Apigee (TASK/CLIENT-03001, code 500.T.02)

application.yaml : QF_CAMUNDA_ASYNC_TIMEOUT_MS / QF_CAMUNDA_LOCK_MS · 17/11/2026

Causeapplication.yamlCD (intégrateur)Vérification

0. Cause

Log du pod (16/11 17:01) : TASK/CLIENT-03001 Exception while fetching and locking task — le corps de la réponse contient "code":"500.T.02", un code d'erreur Apigee (et non du moteur Camunda) : le proxy bpm/v1 coupe l'interrogation du worker (fetchAndLock), qui attend jusqu'à 20 s (async-response-timeout-ms).
Quand la coupure tombe juste après que le moteur a réservé une tâche pour notre worker, la tâche reste bloquée pendant lock-duration-ms (30 s) sans être traitée, puis est reproposée → statut mis à jour avec 30, 60, 90 s de retard ; un re-clic entre-temps donne 409 / 502.
Fix : interroger le moteur moins longtemps que le timeout Apigee (5 s) et réduire la réservation (15 s). Valeurs paramétrables, défauts inchangés en local.

1. application.yaml

SUPPRIMERBloc camunda.worker (AVANT) — Ctrl+F : <code>lock-duration-ms: 30000</code>
fund-management-microservice\fund-management-container\src\main\resources\application.yaml
    lock-duration-ms: 30000
    async-response-timeout-ms: 20000
ÉDITIONAPRÈS
fund-management-microservice\fund-management-container\src\main\resources\application.yaml

Les lignes worker-id, instance et enabled sont inchangées. Rien à changer dans application-local.yaml ni dans le yaml de test.

    lock-duration-ms: ${QF_CAMUNDA_LOCK_MS:30000}                    # durée de réservation d'une tâche prise par le worker
    async-response-timeout-ms: ${QF_CAMUNDA_ASYNC_TIMEOUT_MS:20000}  # attente max d'une interrogation du moteur ; DOIT rester sous le timeout du proxy Apigee

2. CD (intégrateur)

FICHIER NOUVEAUVariables DMZR

QF_CAMUNDA_LOCK_MS=15000
# En local : rien à poser (moteur direct, sans Apigee → 20000 / 30000 par défaut)

3. Vérification

FICHIER NOUVEAUAvant / après
recette\worker-apigee-timeout.txt
1. Avant déploiement : dans les logs de chaque pod, Notepad++ → Find → Count « TASK/CLIENT-03001 » (noter le nombre sur 1 h).
2. Déployer avec les deux variables.
3. Créer et soumettre une demande, Caisse Centrale → Traiter : statut « Traitée » en 1 à 2 s. Idem Annuler (CC et agence).
4. Logs après 1 h : « TASK/CLIENT-03001 » doit être à 0 (ou quasi).
5. S'il en reste : demander à l'équipe Apigee le timeout exact du proxy bpm/v1 et descendre QF_CAMUNDA_ASYNC_TIMEOUT_MS en dessous (ex. 3000).
