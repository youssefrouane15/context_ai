0. Diagnostic

Les 7 erreurs sont toutes dans CashDemandUseCaseImplTest et ont une seule cause : le lot B1 a changé les signatures du use case — create, update, getCashDemandById, search reçoivent maintenant un ContexteAppelant, et cancel reçoit (UUID, AnnulationDemandeDTO, ContexteAppelant). Le test appelle les anciennes signatures.

Deux choses en plus, invisibles à la compilation mais qui feraient échouer les tests à l'exécution :

  1. Le test ne déclare que 3 @Mock pour un constructeur à 8 paramètres. Mockito injecte null pour les 5 autres ; or chaque réponse passe par enrichir() qui appelle cutoffPolicy.journeeCloturee(...) → NPE sur tous les tests. Règle n°6 : 8 @Mock.
  2. create() = initier() + update() : il crée le brouillon et l'instance Camunda avant de valider le contenu. Le test createShouldRejectInvalidRequestWithoutTouchingRepository (un POST invalide ne doit rien écrire) est une bonne règle qu'il faut garder : je valide le contenu avant d'initier (§1). Sans ça, un POST /cash invalide laisserait un brouillon vide avec une instance active.
