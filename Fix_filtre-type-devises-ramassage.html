Fix — le filtre « Commande devises » ramène aussi les ramassages (operationSens manquant)

fund-management-front · 09/10/2026 · 2 éditions

CauseFichiersVérification

0. Cause

Commande de devises et ramassage sont la même famille d'opération côté back : operationType = CURRENCY, seul operationSens les distingue (SUPPLY = commande, COLLECTION = ramassage). Dans construireCriteres(), le filtre « Commande devises » n'envoyait que operationType=CURRENCY → le back renvoyait les deux. « Ramassage » n'envoyait que le sens, ce qui marche aujourd'hui mais par accident (aucune autre opération en COLLECTION).

Correction côté front uniquement : les deux cas envoient operationType et operationSens. Le back accepte déjà les deux critères.

// demandes-list.regles.ts — construireCriteres(…) : ÉDITION du switch (Ctrl+F : case 'CAISSE')
  switch (f.type) {
    case 'CAISSE':    c.operationType = 'CASH_DESK'; break;
    case 'GAB':       c.operationType = 'ATM'; break;
    // Commande de devises et ramassage sont tous deux des opérations CURRENCY : seul le sens les distingue
    // (SUPPLY = commande, COLLECTION = ramassage). Sans le sens, « Commande devises » ramenait aussi les ramassages.
    case 'DEVISES':   c.operationType = 'CURRENCY'; c.operationSens = 'SUPPLY'; break;
    case 'RAMASSAGE': c.operationType = 'CURRENCY'; c.operationSens = 'COLLECTION'; break;
  }

-- Contrôle : une demande ne doit remonter sous « Commande devises » que si elle a une opération CURRENCY + SUPPLY.
select r.unique_request_ref, o.operation_type, o.operation_sens
from retail.cash_request r join retail.cash_operation o on o.cash_request_id = r.id
where o.operation_type = 'CURRENCY'
