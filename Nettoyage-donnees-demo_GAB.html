Demandes GABGAB hors site

Lancer d'abord les requêtes de contrôle (select) : elles montrent exactement ce qui sera modifié. Les instances Camunda des demandes GAB restent bloquées à l'étape « éclater les besoins GAB » (code de BesoinGabPort non déployé en staging) ; sans effet à l'écran pour la démo.

1. Demandes GAB → statut traité

FICHIER COMPLETBase fund-management
pgAdmin — base fund-management

Filtre sur l'agence 9000 : celle de toutes les demandes GAB (références …-9000-xx).

-- Base fund-management (pgAdmin) — demandes GAB hors site (agence 9000) en attente → statut traité

-- Contrôle 1 : nom exact du statut « traité » (valeur portée par les demandes déjà traitées par la Caisse Centrale)
select distinct request_status from retail.cash_request;

-- Contrôle 2 : demandes GAB en attente qui seront modifiées
select id, unique_request_ref, request_status
  from retail.cash_request
 where branch_code = '9000' and request_status = 'SUBMITTED';

-- Mise à jour (remplacer 'VALIDATED' si le contrôle 1 affiche un autre nom pour le statut traité)
update retail.cash_request
   set request_status = 'VALIDATED', modification_date = now()
 where branch_code = '9000' and request_status = 'SUBMITTED';

2. GAB hors site créés pendant la recette

FICHIER COMPLETBase utilisateurs-ci
pgAdmin — base utilisateurs-ci, schéma qf_admin
-- Base utilisateurs-ci (pgAdmin, schéma qf_admin) — GAB hors site créés à la main pendant la recette
-- Les 56 GAB du fichier PO (chargés par la V21) sont conservés.

-- Contrôle : GAB ajoutés après le chargement initial
select id, id_gab, nom, created_at
  from qf_admin.gab_hors_site
 where created_at > (select installed_on from qf_admin.flyway_schema_history where script like 'V21__%');

-- Suppression
delete from qf_admin.gab_hors_site
 where created_at > (select installed_on from qf_admin.flyway_schema_history where script like 'V21__%');
