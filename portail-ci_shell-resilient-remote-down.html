Cause et principeFichiersRecette

0. Cause et principe

Cause : main.ts appelle initFederation('/assets/mf.manifest.json') qui, par défaut, télécharge tous les remoteEntry.js du manifest avant le bootstrap. Si fund-management-front est arrêté, la promesse rejette (ERR_CONNECTION_REFUSED, « Failed to fetch dynamically imported module »), import('./bootstrap') n'est jamais appelé → page blanche. C'est l'erreur que tu avais partagée.

Fix (3 pièces) : (1) initFederation(manifest, true) — skipRemoteEntries : le manifest est enregistré, les remoteEntry.js sont chargés à la demande par loadRemoteModule (route /portail, CHARGEUR_MENU_GESFOND), qui ont déjà chacun leur catch côté menu ; (2) la route /portail retombe sur une page « module indisponible » au lieu d'une navigation en erreur ; (3) le bootstrap a lieu quoi qu'il arrive.

Manifest depuis app-config.json : initFederation accepte un objet { remoteName: url } aussi bien qu'une URL de fichier. L'URL du remote est désormais fundManagementUrl + '/remoteEntry.js' (clé déjà présente dans config/app-config.json et environment) ; assets/mf.manifest.json disparaît — l'intégrateur n'a plus qu'un fichier à écraser. La config est donc chargée avant la fédération, dans main.ts ; configuration.ts n'importe rien d'Angular, il peut y être importé sans casser le graphe partagé.

/**
 * Module Federation : le manifest n'est plus un fichier d'assets (mf.manifest.json) mais est dérivé de config/app-config.json
 * (clé fundManagementUrl, écrasée par le CD de l'intégrateur) → une seule source d'URL d'environnement.
 */
export const REMOTE_GESFOND = 'qlickFlowFMFront';

/** Manifest attendu par initFederation / loadRemoteModule({ type: 'manifest', remoteName }). */
export function manifestFederation(fundManagementUrl: string): Record<string, string> {
  const base = (fundManagementUrl || '').replace(/\/+$/, '');
  return { [REMOTE_GESFOND]: `${base}/remoteEntry.js` };
}

import { initFederation } from '@angular-architects/module-federation';
import { chargerConfiguration } from './app/core/config/configuration';
import { manifestFederation } from './app/core/config/federation';
import { environment } from './environments/environment';

/*
 * Ordre de démarrage du shell :
 *  1. config/app-config.json → environment (apiUrl, fundManagementUrl…) — AVANT la fédération, qui a besoin de l'URL du remote ;
 *  2. initFederation avec le manifest dérivé de la config, skipRemoteEntries = true : remoteEntry.js n'est plus téléchargé ici
 *     mais à la demande (route /portail, menu GesFond). Un micro-frontend arrêté ne bloque donc plus le portail ;
 *  3. bootstrap Angular, quoi qu'il arrive.
 * Aucun import @angular/* dans ce fichier : il doit rester hors du graphe partagé (d'où le import('./bootstrap') dynamique).
 */
(async () => {
  try {
    await chargerConfiguration();
  } catch (err) {
    console.error('[config] chargement impossible, le portail démarre avec les valeurs du build', err);
  }
  try {
    await initFederation(manifestFederation(environment.fundManagementUrl), true);
  } catch (err) {
    console.error('[mf] initialisation de la fédération impossible — le portail continue sans micro-frontend', err);
  }
  await import('./bootstrap');
})().catch(err => console.error(err));

Pré-requis : portail-ci avec la config externalisée (app-config.json : apiUrl + fundManagementUrl), fund-management-front sur 4201.

A. Remote arrêté (ne PAS lancer ng serve du MFE)
   1. http://localhost:4200 → le portail s'affiche (login, dashboard). Console : aucune erreur « Failed to fetch dynamically imported module …/remoteEntry.js » au démarrage.
      Network : GET config/app-config.json = 200 ; AUCUNE requête remoteEntry.js avant le clic.
   2. Dashboard → carte « Gestion des fonds » → ACCÉDER → page « Module momentanément indisponible » + bouton Retour ; console : « [mf] Gestion des fonds indisponible ».
      Le header / menu du portail restent fonctionnels ; Dérogation, Mainlevée, Droits de com inchangés.
   3. Retour à l'accueil → dashboard.

B. Remote démarré
   4. ng serve du MFE (4201). F5 sur le portail (obligatoire : un import() échoué reste en échec dans le navigateur jusqu'au rechargement).
   5. Carte Gestion des fonds → écran GesFond, menu GesFond chargé (CHARGEUR_MENU_GESFOND). Network : remoteEntry.js chargé APRÈS le clic, depuis fundManagementUrl.
   6. Changer "fundManagementUrl" dans src/config/app-config.json vers http://localhost:9999 → F5 → clic carte → page indisponible (preuve que le manifest vient du fichier). Remettre 4201.
