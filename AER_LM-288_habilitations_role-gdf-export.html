Un seul point flou dans la Jira : « Caisse Centrale : droit à la mise à jour ». Aujourd'hui la Caisse Centrale ne modifie pas le contenu d'une demande (elle décide : Traiter / Annuler avec motif) ; c'est l'agence qui met à jour. Si le PO veut que la Caisse Centrale puisse éditer le contenu, c'est un chantier séparé (verrou de modification côté CC, BPMN). Ce doc ne le traite pas ; je pose la question à côté.

Ordre : §1 users (enum + V18, redémarrage) → §2 fund-management → §3 front → §4 vérification. La chaîne est déjà en place : users expose les permissions du profil sur /me et sur l'endpoint interne, fund-management les transforme en authorities, le front les dérive en HabilitationsGdf. Rien à faire dans la gateway ni dans le BPMN.

-- AER_LM-288 : rôle « GDF Export » (permission GDF_EXPORTER_DEMANDE) rattaché aux profils Caisse Centrale (10) et Support (11).
-- Idempotent : chaque INSERT est protégé par NOT EXISTS. Les ids suivent V16 (rôles 10-12, profils 9-11).

INSERT INTO hab_roles (id, name, description, actif, created_at, updated_at, platform)
SELECT 13, 'GDF Export', 'Gestion des fonds - Export Excel des demandes', true, now(), now(), 'GESTION_FONDS'
WHERE NOT EXISTS (SELECT 1 FROM hab_roles WHERE id = 13 OR name = 'GDF Export');

INSERT INTO hab_role_permission (role_id, permission)
SELECT 13, 'GDF_EXPORTER_DEMANDE'
WHERE NOT EXISTS (SELECT 1 FROM hab_role_permission WHERE role_id = 13 AND permission = 'GDF_EXPORTER_DEMANDE');

-- Profil 10 = CAISSE_CENTRALE, profil 11 = SUPPORT (V16)
INSERT INTO hab_profile_role (profile_id, role_id)
SELECT p.id, 13 FROM hab_profiles p
WHERE p.code IN ('CAISSE_CENTRALE', 'SUPPORT')
  AND NOT EXISTS (SELECT 1 FROM hab_profile_role pr WHERE pr.profile_id = p.id AND pr.role_id = 13);

-- La séquence des rôles ne doit pas redistribuer l'id 13 (même convention que V6 / V16)
SELECT setval(pg_get_serial_sequence('hab_roles', 'id'), (SELECT MAX(id) FROM hab_roles));

pgAdmin (base utilisateurs-ci, schéma qf_admin) — à lancer avant et après V18
-- Avant : ce que chaque profil GDF détient aujourd'hui (attendu : Agence = CONSULTER/CREER/MODIFIER/ANNULER ;
-- Caisse Centrale = CONSULTER/TRAITER/TOUTES_AGENCES [+ ANNULER selon V16] ; Support = CONSULTER/TOUTES_AGENCES)
set search_path to qf_admin;
SELECT p.code AS profil, r.id AS role_id, r.name AS role, string_agg(rp.permission, ', ' ORDER BY rp.permission) AS permissions
FROM hab_profiles p
JOIN hab_profile_role pr ON pr.profile_id = p.id
JOIN hab_roles r ON r.id = pr.role_id
LEFT JOIN hab_role_permission rp ON rp.role_id = r.id
WHERE r.platform = 'GESTION_FONDS'
GROUP BY p.code, r.id, r.name
ORDER BY p.code, r.id;
