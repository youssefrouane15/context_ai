0. Le problème en une phrase

Après « Traiter la demande », decision_par / decision_profil / decision_at sont null en base alors que figerDecision est bien appelé. Cause la plus probable : quelques secondes après ton clic, le worker Camunda pose le statut VALIDATED en sauvegardant la demande complète ; comme le mapper domaine → entité ignore les trois champs décision, cette sauvegarde les remet à null. Deuxième cause possible, moins probable : une transaction en lecture seule sur le use case qui empêche l'écriture de figerDecision.

Les étapes ci-dessous corrigent les deux d'un coup, dans l'ordre. Compte 15 minutes.

1. Étape 1 — Mapper de persistance : retirer les « ignore »

SUPPRIMERCashRequestPersistenceMapper (data-access)
C:\dev\fund-management-microservice\fund-management-data-access\…\CashRequestPersistenceMapper.java (Ctrl+F : decisionPar)
// fund-management-data-access — CashRequestPersistenceMapper (le MapStruct entité <-> domaine)
// Ctrl+F : decisionPar   → tu dois trouver les 3 lignes ci-dessous. SUPPRIME-LES, quelle que soit la méthode qui les porte

-- Attendu : la demande traitée a decision_par = ton nom complet (ou ton uid), decision_profil = ton profil, decision_at = l'heure du clic,
