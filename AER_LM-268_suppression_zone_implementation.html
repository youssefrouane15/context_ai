1. Pourquoi ce n'était pas dans la 268

Le bouton SUPPRIMER est inerte sur les onglets Agence(s) / Groupe(s) / Zone(s) (aucun (click), deleteAgence / deleteZone « no usages » dans OrganizationService), et le contrôleur ZoneDistributionController livré en 270 n'expose pas de DELETE. J'ai donc reproduit l'existant. Pour rendre la suppression fonctionnelle il faut quatre choses, livrées ici.

Règle métier retenue
Une zone de distribution référencée par au moins une agence (agence.zone_distribution_id, FK posée en V15) ne se supprime pas : le serveur répond 400 avec un message explicite affiché dans la modale, l'administrateur désactive la zone (toggle existant) ou réaffecte les agences. Sans ce contrôle, la FK ferait échouer le DELETE en 500. Pas de suppression logique : actif joue déjà ce rôle.

À AJOUTERZoneDistributionService — méthode (après toggleActivation)
Imports : jakarta.persistence.EntityNotFoundException (même exception que les autres 404 du service) et org.springframework.transaction.annotation.Transactional. Le message d'erreur est en français car il est affiché tel quel dans la modale (handleError remonte error.error.message).
    /**
     * Supprime une zone de distribution.
     * Refusée (400, message affiché dans la modale) si au moins une agence y est rattachée :
     * l'administrateur doit d'abord réaffecter les agences ou désactiver la zone.
     */
    @Transactional
    public void deleteZoneDistribution(Long id) {
        ZoneDistributionEntity zone = zoneDistributionRepository.findById(id)
                .orElseThrow(() -> new EntityNotFoundException("ZoneDistribution not found with id: " + id));

        if (agenceRepository.existsByZoneDistributionId(id)) {
            throw new IllegalArgumentException(
                    "La zone de distribution " + zone.getCode()
                    + " est rattachée à une ou plusieurs agences et ne peut pas être supprimée. Désactivez-la ou réaffectez les agences.");
        }

        zoneDistributionRepository.delete(zone);
    }
À AJOUTERZoneDistributionFacade — délégation
    public void deleteZoneDistribution(Long id) {
        zoneDistributionService.deleteZoneDistribution(id);
    }
À AJOUTERZoneDistributionController — endpoint
Reprendre l'autorité du @PreAuthorize du @PutMapping du même contrôleur, et la forme exacte de ApiResponse.success(...) utilisée par le @PatchMapping toggle (message en anglais, convention des messages API). Import DeleteMapping.
    @DeleteMapping("/{id}")
    @PreAuthorize("hasAuthority('<même autorité que le @PutMapping de ce contrôleur>')")
    public ResponseEntity<ApiResponse<Void>> deleteZoneDistribution(@PathVariable Long id) {
        zoneDistributionFacade.deleteZoneDistribution(id);
        return ResponseEntity.ok(ApiResponse.success(null, "ZoneDistribution deleted successfully"));
    }
Alternative 409
Si le tech lead préfère un 409 Conflict à un 400, créer une ResourceInUseException et son @ExceptionHandler dans GlobalExceptionHandler sur le modèle de handleNotFound ; le front n'a rien à changer, il affiche le message quel que soit le statut.

  confirmDeleteZoneTransporteur(): void {
    if (!this.zoneTransporteurASupprimer) {
      return;
    }
    this.referentielService.deleteZoneDistribution(this.zoneTransporteurASupprimer.id).subscribe({
      next: () => {
        this.loadZonesTransporteur();
        this.closeDeleteZoneTransporteurModal();
      },
      error: (error) => {
        this.errorMessage = error.message || 'Erreur lors de la suppression de la zone transporteur.';
      }
    });
  }
