Fix accès Gestion des fonds sans habilitation (Super Admin) + ÉDITER réservé aux utilisateurs GDF

0. Cause

Le Super Admin n'a aucune habilitation Gestion des fonds dans fund-management-front. En arrivant sur /portail, la route '' exécute accueilParProfil puis exigePermission('creer'), et exigePermission renvoie false : Angular annule la navigation sans rien afficher → on reste sur le dashboard, aucun appel, aucun message.
Fix (aucun droit ajouté au SA) : les gardes ne renvoient plus jamais false, elles redirigent vers une page « aucun accès » du module. Une garde d'entrée accesGestionFonds est placée en premier sur '' pour court-circuiter accueilParProfil quand l'utilisateur n'a aucune habilitation.

/**
 * Page « aucun accès » sous le préfixe où le module est monté (/portail dans le shell, racine en autonome 4201).
 * Une garde qui renvoie false annule la navigation EN SILENCE (clic sans effet) : on redirige toujours vers cette page.
 */
function versAucunAcces(router: Router, route: ActivatedRouteSnapshot): UrlTree {
  const prefixe = (route.parent?.pathFromRoot ?? []).flatMap(r => r.url.map(segment => segment.path));
  return router.createUrlTree(['/', ...prefixe, 'aucun-acces']);
}

/** Entrée du module : un utilisateur sans aucune habilitation Gestion des fonds (ex. Super Admin) va sur « aucun accès ». */
const accesGestionFonds: CanActivateFn = async (route) => {
  const router = inject(Router);
  const ctx = await inject(ContexteUtilisateurService).charger();
  const auMoinsUneHabilitation = ctx !== null && Object.values(ctx.habilitations).some(Boolean);
  return auMoinsUneHabilitation || versAucunAcces(router, route);
};

const exigePermission = (cle: keyof HabilitationsGdf): CanActivateFn => async (route) => {
  const router = inject(Router);
  const ctx = await inject(ContexteUtilisateurService).charger();
  return (ctx !== null && ctx.habilitations[cle]) || versAucunAcces(router, route);
};

3. Évolution — ÉDITER réservé aux utilisateurs habilités Gestion des fonds

Règle : sur chaque ligne, ÉDITER n'est actif que si l'utilisateur de la ligne a au moins une permission GDF_ dans les rôles de son profil. On réutilise extractUserPermissions (déjà utilisé par AuthService.hasPermission, même type UserDTO) : aucun nouveau type, aucun appel en plus. Le bouton reste affiché, grisé avec une infobulle ; editUser refuse aussi par sécurité.
