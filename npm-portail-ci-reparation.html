Réparer npm install derrière le réseau BMCI
— la checklist complète, dans l'ordre

Le diagnostic établi ensemble : le fichier s'appelait npmrc sans le point (donc ignoré), puis une fois lu, Artifactory (zone groupe France) répondait Socket timeout — joignable soit en direct via VPN, soit via le proxy vip-svc-sra-prx. Cette fiche déroule tout, du rename au npm install qui passe.

🧾Symptôme 1 — npm ERR! network… behind a proxy : npm visait npmjs.org en direct, le .npmrc n'était pas lu.
🧾Symptôme 2 — FETCH_ERROR / Socket timeout sur repo.artifactory-dogen : le registry est bon, mais la route réseau ne passe pas.
1Le point qui change tout

Renommer npmrc en .npmrc

npm ne lit que le fichier nommé .npmrc (avec le point). L'Explorateur Windows refuse parfois ce renommage — PowerShell, lui, ne discute pas :

PowerShell 
Rename-Item C:\Users\j43709\npmrc .npmrc

Si tu as déjà fait ce renommage, passe directement à l'étape 2 — elle vérifie que tout est en ordre.

2Le test de vérité

Vérifier que npm lit bien le fichier

PowerShell 
npm config get registry
✅ Affiche l'URL Artifactory

https://repo.artifactory-dogen.group.echonet/...

Le .npmrc est lu. Continue à l'étape 3.

❌ Affiche https://registry.npmjs.org/

Le fichier n'est toujours pas lu : vérifie le nom exact (.npmrc, pas .npmrc.txt — affiche les extensions dans l'Explorateur) et l'emplacement (C:\Users\j43709\).

3La bifurcation

VPN allumé : Artifactory est-il joignable en direct ?

Ton indice était bon : Git fonctionne en direct via VPN, sans proxy. Artifactory est dans la même zone réseau que GitLab dogen — il est donc possible que le VPN suffise, et que le Socket timeout soit arrivé VPN coupé. On tranche en 5 secondes :

PowerShell — VPN CONNECTÉ 
Test-NetConnection repo.artifactory-dogen.group.echonet -Port 443
✅ TcpTestSucceeded : True

Pas besoin de proxy. Saute l'étape 4, va directement à l'étape 5 (npm install), et garde le réflexe : npm install = VPN allumé.

❌ TcpTestSucceeded : False

La route directe n'existe pas depuis ton poste : il faut passer par le proxy. Étape 4 obligatoire.

4Seulement si le test est False

Ajouter le proxy dans le .npmrc — version corrigée, pas copiée

Le proxy de Hamza (vip-svc-sra-prx.fr.xcp.net.intra:3132) est une infrastructure partagée : valable pour toi. Ce qui est personnel dans sa ligne, c'est f42747:@Casa*1984 — son matricule et son mot de passe. Toi tu mets j43709 + ton mot de passe AD.

4a. Encoder ton mot de passe

Dans une URL de proxy, certains caractères ont un sens spécial et doivent être remplacés :

CaractèreÀ écrireCaractèreÀ écrire
@%40:%3A
#%23/%2F
%%25?%3F
&%26espace%20
=%3D* ! - _ .inchangés

Exemple : un mot de passe @Casa*1984 s'écrit %40Casa*1984.

4b. Ajouter ces deux lignes au fichier C:\Users\j43709\.npmrc

.npmrc — lignes à AJOUTER (garde les lignes existantes de Yassin) 
proxy=http://j43709:TON_MDP_ENCODE@vip-svc-sra-prx.fr.xcp.net.intra:3132
https-proxy=http://j43709:TON_MDP_ENCODE@vip-svc-sra-prx.fr.xcp.net.intra:3132
3 corrections vs le message de Hamza ① https-proxy commence bien par http:// — on parle au proxy en HTTP même pour du trafic HTTPS ; son https://f42747... passe parfois sur Git mais fait planter npm.  ② Le mot de passe doit être encodé (tableau ci-dessus) — c'est le double @ de sa ligne qui rendait l'URL ambiguë.  ③ Ne recopie pas son git config http.sslVerify false — c'est le réflexe qu'on a déjà désinstallé chez toi ; le strict-ssl=false déjà présent dans le .npmrc couvre le cas npm.

4c. Astuce : d'abord sans identifiants

Certains proxys internes laissent passer les postes du domaine sans login. Essaie d'abord la version courte — si elle donne une erreur 407, repasse à la version avec j43709:MDP@ :

.npmrc — variante à tester en premier 
proxy=http://vip-svc-sra-prx.fr.xcp.net.intra:3132
https-proxy=http://vip-svc-sra-prx.fr.xcp.net.intra:3132
5Le lancement

Relancer l'installation

PowerShell — dans C:\dev\portail-ci 
cd C:\dev\portail-ci
npm install
Bon à savoir Artifactory est un miroir : la première fois qu'on lui demande un paquet, il va lui-même le chercher sur npmjs.org puis le garde en cache. Des timeouts isolés au premier passage sont normaux → relance npm install une ou deux fois, le miroir se remplit. Pas besoin de npm cache clean entre chaque essai.

Si les timeouts isolés persistent, rends npm plus patient en ajoutant au .npmrc :

.npmrc — patience augmentée (optionnel) 
fetch-timeout=120000
fetch-retries=5
fetch-retry-maxtimeout=120000

Deux points d'hygiène à ne pas oublier

🔑 Tes propres identifiants Artifactory

Les lignes username=f39128 / _password=... du .npmrc sont le compte de Yassin. Ça dépanne, mais demande-lui comment générer les tiens : le jour où son mot de passe tourne, ton install casse sans prévenir — et côté audit, chaque téléchargement que tu fais est signé de son nom.

🔁 Le jour où ton mot de passe AD change

Si tu as mis tes identifiants dans les lignes proxy : mets à jour le .npmrc immédiatement après un changement de mot de passe. Sinon npm réessaie en boucle avec l'ancien → 407 en rafale → compte AD verrouillé. C'est le piège classique déjà croisé avec Git.

La chaîne complète, pour mémoire npm → (VPN direct ou proxy vip-svc-sra-prx:3132) → Artifactory dogen (miroir) → npmjs.org. Le .npmrc porte trois infos : où est le registre (registry), qui je suis pour lui (username/_password), et par où je passe (proxy/https-proxy). Quand une install échoue, l'erreur te dit laquelle des trois est en cause.
