0. Pourquoi ça cassait

Quand on ouvre Gestion des fonds, Angular déroule la navigation dans un ordre fixe :
1. canMatch → 2. canActivate (les guards) → 3. resolve → affichage.

Le chargement de app-config.json était en 3 (resolve). Mais le guard exigePermission, en 2, appelle /me pour vérifier les droits. Donc /me partait avant que l'URL de la gateway soit connue : gatewayUrl valait encore \'\', l'appel devenait /api/v1/public/users/me tout court, et le navigateur l'envoyait à l'adresse du front.

En local ça marchait par hasard : environment.ts contient déjà localhost:9090, donc même sans le fichier l'URL était bonne.

Correctif : charger la config en 1 (canMatch), qui passe avant tous les guards.

/**
 * Sous le shell portail, app.config.ts du remote ne s'exécute pas : le chargement est garanti par ce guard canMatch
 * sur la route racine exposée (app.routes.ts). canMatch s'exécute avant tous les canActivate (dont exigePermission → /me) ;
 * même promesse que l'initialiseur → aucun double appel. Toujours true : une config absente est gérée par chargerConfiguration.
 */
export const CONFIGURATION_AVANT_NAVIGATION: CanMatchFn = () => chargerConfiguration().then(() => true);
